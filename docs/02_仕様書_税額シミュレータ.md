## 1. システム構成

### 1.1 アーキテクチャ方針

**完全クライアントサイド SPA（サーバーなし）**。所得情報という機微データを扱うため、ネットワークにデータを出さない構成を必須とする（NFR-01）。

```
┌─────────────────────────────────────────┐
│  UI 層 (React + TypeScript)             │
│   画面コンポーネント / フォーム / グラフ    │
├─────────────────────────────────────────┤
│  状態管理層 (Zustand)                    │
│   入力状態・シナリオ・再計算トリガ         │
├─────────────────────────────────────────┤
│  ドメイン層 ★ここが本体                   │
│   ├ income.ts       給与所得・月次按分     │
│   ├ deductions.ts   所得控除              │
│   ├ incomeTax.ts    所得税                │
│   ├ residentTax.ts  住民税                │
│   ├ housingLoan.ts  住宅ローン控除         │
│   ├ furusato.ts     上限額探索            │
│   └ warnings.ts     警告エンジン          │
│   ※すべて純粋関数。副作用・UI依存なし      │
├─────────────────────────────────────────┤
│  パラメータ層                             │
│   taxParams/2025.json, 2026.json ...     │
├─────────────────────────────────────────┤
│  永続化層                                │
│   ├ repository.ts  IndexedDB CRUD        │
│   ├ migration.ts   schemaVersion 移行     │
│   ├ exporter.ts    JSON書き出し／暗号化   │
│   └ settings.ts    localStorage（軽量設定）│
└─────────────────────────────────────────┘
          ↓ ビルド（Vite）
   静的ファイル一式 → GitHub Pages
   （サーバーサイド処理・環境変数・シークレットは一切なし）
```

**人物レイヤーの位置づけ**: ドメイン層は「1人物・1年分」を入力とする純粋関数のままとし、人物の切替は状態管理層の責務とする。これにより計算エンジンは複数ユーザー対応の影響を受けない。

### 1.2 技術スタック

| 領域 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript (strict) | 金額型の取り違え防止、税制モデルの型表現 |
| ビルド | Vite | 軽量、PWAプラグインあり |
| UI | React 18 | |
| 状態管理 | Zustand | 単一ユーザー・単一ストアで十分 |
| グラフ | Recharts | 積み上げ棒・折れ線 |
| テスト | Vitest | ドメイン層の単体テストが本アプリの品質の中心 |
| 永続化 | IndexedDB（`idb` ラッパー）/ localStorage（軽量設定のみ） | 構造化データを扱え、容量上限が大きい |
| 暗号化 | Web Crypto API（AES-GCM + PBKDF2） | 外部ライブラリ不要 |
| ルーティング | ルーター不使用（タブ状態管理）または HashRouter | GitHub Pages はSPAフォールバックを持たないため（§1.4.3） |
| PWA | vite-plugin-pwa | Service Worker とマニフェストの生成 |
| フォント | OS標準フォント（`system-ui`）のみ。Webフォントは読み込まない | 外部通信を発生させない。金額の桁揃えは `tabular-nums` で満たす。§1.4.6 |
| 配信 | GitHub Pages（GitHub Actions でビルド＆デプロイ） | サーバー不要・無料・独自ドメイン可 |

### 1.3 金額の扱い

- すべて **整数（円）** で保持する。`number` 型だが小数を持たせない。
- 除算・乗算後は必ず明示的な端数処理関数を通す。

```ts
type Yen = number & { readonly __brand: 'Yen' };

const floorTo   = (v: number, unit: number): number => Math.floor(v / unit) * unit;
const floor1000 = (v: number) => floorTo(v, 1000);  // 課税所得
const floor100  = (v: number) => floorTo(v, 100);   // 税額
const floorYen  = (v: number) => Math.floor(v);
```

### 1.4.2 Vite 設定（サブパス対応）

`https://<user>.github.io/<repo>/` で配信されるため、`base` の設定が必須。

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { VitePWA } from 'vite-plugin-pwa';

const base = process.env.VITE_BASE ?? '/kojin-tax-sim/';

export default defineConfig({
  base,
  plugins: [
    react(),
    VitePWA({
      registerType: 'prompt',          // 自動更新でなく明示的に更新を促す（NFR-14）
      manifest: {
        name: '個人税額・ふるさと納税シミュレータ',
        short_name: 'TaxSim',
        start_url: base,               // ★サブパスを含めること
        scope: base,                   // ★同上
        display: 'standalone',
        background_color: '#ffffff',
        theme_color: '#1f2937',
      },
      workbox: {
        globPatterns: ['**/*.{js,css,html,svg,png,webmanifest}'],
        runtimeCaching: [
          {
            // 税制パラメータは NetworkFirst にし、古い版の固着を防ぐ（R-10）
            urlPattern: /taxParams\/.*\.json$/,
            handler: 'NetworkFirst',
            options: { cacheName: 'tax-params', expiration: { maxAgeSeconds: 60 * 60 * 24 } },
          },
          {
            // フォント本体（不変。1年キャッシュ）
            urlPattern: /^https:\/\/fonts\.gstatic\.com\//,
            handler: 'CacheFirst',
            options: {
              cacheName: 'google-fonts-webfonts',
              cacheableResponse: { statuses: [0, 200] },   // ★opaque応答を許可
              expiration: { maxEntries: 30, maxAgeSeconds: 60 * 60 * 24 * 365 },
            },
          },
          {
            // CDN配信のライブラリ（バージョン固定URLのみ）
            urlPattern: /^https:\/\/cdn\.jsdelivr\.net\//,
            handler: 'CacheFirst',
            options: {
              cacheName: 'cdn-libs',
              cacheableResponse: { statuses: [0, 200] },
              expiration: { maxEntries: 30, maxAgeSeconds: 60 * 60 * 24 * 365 },
            },
          },
        ],
      },
    }),
  ],
});
```

**注意点**

| 項目 | 対応 |
|---|---|
| アセット参照 | 絶対パス `/foo.png` は使わない。`import.meta.env.BASE_URL` を経由するか、`import` によるバンドルを使う |
| `taxParams` の取得 | `fetch(`${import.meta.env.BASE_URL}taxParams/2026.json`)` |
| `.nojekyll` | GitHub Pages の Jekyll 処理を無効化するため、出力ルートに空ファイルを配置（`_` で始まるファイルが無視されるのを防ぐ） |

### 1.4.3 ルーティング

GitHub Pages は 404 時に `index.html` を返さないため、History API ベースの SPA ルーティングは直リンクで壊れる。対策は次のいずれか。

| 方式 | 評価 |
|---|---|
| **ルーターを使わない**（画面切替を状態で管理） | **推奨**。本アプリは画面数が少なく、URL共有の必要もない。最もシンプル |
| HashRouter（`#/dashboard`） | URLを持たせたい場合。GitHub Pages で確実に動く |
| `404.html` にリダイレクトスクリプトを置く | 動くが URL が一瞬書き換わるなど癖がある。採用しない |

### 1.4.4 デプロイワークフロー

```yaml
# .github/workflows/deploy.yml
name: Deploy to GitHub Pages
on:
  push: { branches: [main] }
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run test          # ★テストが落ちたらデプロイしない
      - run: npm run build
      - run: touch dist/.nojekyll
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

**計算エンジンのテストをデプロイの前提条件にする**こと。税額を誤ったまま公開されるのが最悪のケースであるため、`npm run test` の失敗はデプロイをブロックする。

### 1.4.5 外部通信ポリシー（NFR-01 / NFR-15）

**禁止するのは「データを送る通信」であり、「アセットを取る通信」ではない。**

| 区分 | 可否 | 実装上の扱い |
|---|---|---|
| Google Fonts、CDN からのアセット取得 | ⛔ 使用しない | 要件上は許可されるが（要件定義書§7.1）、実装では外部アセットを一切使わずビルド成果物のみで完結させている（§1.4.6） |
| 外部スクリプトの読み込み | ✅ 許可 | **バージョン固定URL**＋`integrity`（SRI）＋`crossorigin="anonymous"` を必須とする |
| 入力値を含む送信 | ❌ 禁止 | 実装しない |
| アナリティクス | ⚠️ 条件付き | 導入する場合、イベントパラメータに金額・入力値を含めない |
| エラー収集 | ⚠️ 条件付き | 変数キャプチャ・DOM Breadcrumb を無効化し、`beforeSend` でスクラビング。困難なら導入しない |

**CDN 利用時の必須要件**

1. **バージョンを固定する**（`@latest` を使わない）。税額計算のロジックが依存するライブラリが黙って変わるのは許容できない。
2. **CDN 障害時にアプリが起動不能にならないこと**。計算エンジン・状態管理・永続化など**コア機能の依存はすべてバンドルに含める**。CDN に置いてよいのは、欠けても操作を継続できるもの（フォント、任意のアイコンセット、印刷用スタイル等）に限る。
3. **初回アクセスはオンライン前提でよい**が、2回目以降はSWキャッシュによりオフラインで完全動作すること。

```html
<!-- 外部スクリプトを使う場合の書式 -->
<script src="https://cdn.jsdelivr.net/npm/example@1.2.3/dist/example.min.js"
        integrity="sha384-..." crossorigin="anonymous"></script>
```

### 1.4.6 フォント指定

金額を扱うアプリのため、**数字の見え方**を最優先で選ぶ。

Webフォントは読み込まず、OS標準フォントのみを使う。外部フォントの取得は利用者のIPアドレスとリファラを第三者に渡すうえ、オフライン動作（NFR-15）の条件も増える。桁揃えという本来の目的は `font-variant-numeric: tabular-nums` で満たせるため、フォントの取得自体を行わない。

```css
:root {
  --font-sans: system-ui, sans-serif;
  --font-numeric: system-ui, sans-serif;
}

/* 金額表示は等幅数字にし、桁が揃うようにする */
.amount {
  font-family: var(--font-numeric);
  font-variant-numeric: tabular-nums;
  font-feature-settings: 'tnum' 1;
}
```

| 指針 | 内容 |
|---|---|
| 等幅数字 | `font-variant-numeric: tabular-nums` を金額セルに必ず適用。計算明細（S-05）で桁がずれると検算できない |
| 外部取得なし | `<link>` による Google Fonts 等の読み込みは行わない。Service Worker の `runtimeCaching` にもフォント向けの規則を置かない |
| フォールバック | `system-ui` が解決できない環境でもレイアウトが崩れないよう、`sans-serif` を末尾に置く |

> 将来 Webフォントを使う場合は、第三者へのIP露出とオフライン動作の両方を避けるためセルフホスト（`@fontsource/*` 等）にする。後から差し替えられるよう、フォント指定は CSS 変数に集約してある。

## 2. データモデル

### 2.1 ルートデータ構造（複数ユーザー対応）

```ts
/** IndexedDB に保存されるルート。エクスポートJSONもこの形 */
interface AppData {
  schemaVersion: number;              // 現行: 2（v2で社会保険料の内訳フィールドを追加）
  exportedAt?: string;                // ISO8601。エクスポート時のみ
  appVersion?: string;                // 生成したアプリのバージョン
  persons: Person[];
  activePersonId: string | null;
  appSettings: AppSettings;           // 人物に依らない設定
}

/** 人物（世帯メンバー） */
interface Person {
  id: string;                         // UUID
  displayName: string;                // 例: '本人' '配偶者'。本名の入力は強制しない
  color: string;                      // 識別色 (#RRGGBB)
  createdAt: string;
  updatedAt: string;
  /** 人物ごとの年度プロファイル。key は西暦年 */
  years: Record<number, YearProfile>;
  /** この人物の既定値（自治体など。新しい年度を作るときの初期値） */
  defaults: {
    municipality: MunicipalityConfig;
    safetyRatio: number;
  };
}

interface AppSettings {
  lastExportedAt: string | null;                  // FR-28 バックアップ督促用
}
```

**設計上のポイント**

- `Person` は `YearProfile` を内包する。人物削除＝そのレコードの削除で完結し、孤児データが残らない（NFR-12）。
- 計算エンジンの入力は従来どおり `YearProfile` 単体であり、人物の概念を持ち込まない。テストの独立性が保たれる。
- `schemaVersion` を**ルートに1つだけ**持ち、移行はルート単位で行う（§2.4.3）。

### 2.2 入力

```ts
/** 年度プロファイル（1年分の入力すべて） */
interface YearProfile {
  year: number;                       // 例: 2026
  municipality: MunicipalityConfig;   // 自治体設定
  income: IncomeInput;
  deductions: DeductionInput;
  housingLoan?: HousingLoanInput;
  furusato: FurusatoInput;
  actuals?: ActualValues;             // 検算モード用の実績値
}

/** 収入 */
interface IncomeInput {
  monthly: MonthlyRecord[];           // 長さ12
  bonuses: Bonus[];
  leavePeriods: LeavePeriod[];        // 育休・産休など
  otherSalaryIncome: number;          // 他の支払者からの給与（年額）
}

interface MonthlyRecord {
  month: number;                      // 1-12
  status: 'actual' | 'estimated';     // 実績か見込みか
  grossSalary: number;                // 課税支給額（通勤手当等の非課税分は除く）
  socialInsurance: number;            // 一括入力時の社会保険料（健保+厚年+雇用保険、本人負担）
  isSocialInsuranceExempt: boolean;   // 育休による免除
  /** 社会保険料の入力方法。省略時は 'total'（一括入力） */
  socialInsuranceInputMode?: 'total' | 'breakdown';
  /** 内訳入力時の値。'total' に戻しても保持し、再度切り替えたときに復元する */
  socialInsuranceBreakdown?: SocialInsuranceBreakdown;
}

/** 給与明細の項目に合わせた社会保険料の内訳。該当しない項目（40歳未満の介護保険料など）は0円 */
interface SocialInsuranceBreakdown {
  healthInsurance: number;       // 健康保険料
  nursingCare: number;           // 介護保険料
  pension: number;               // 厚生年金保険料
  employmentInsurance: number;   // 雇用保険料
  other: number;                 // その他（厚生年金基金など）
}

interface Bonus {
  label: string;                      // 例: '夏季賞与'
  month: number;
  status: 'actual' | 'estimated';
  gross: number;
  socialInsurance: number;
  isExempt: boolean;                  // 1ヶ月超の育休期間中で免除
}

interface LeavePeriod {
  type: 'childcare' | 'maternity' | 'other';
  startYm: string;                    // 'YYYY-MM'
  endYm: string;
  /** 非課税給付（税計算には算入しないが、手取り把握のために保持） */
  benefitAmount: number;
}

/** 所得控除 */
interface DeductionInput {
  socialInsuranceOverride?: number;      // 月次合計を使わず総額指定する場合
  lifeInsurance: LifeInsuranceInput;
  earthquakeInsurance: { long: number; short: number };
  medical: MedicalInput;
  ideco: number;                          // 小規模企業共済等掛金
  spouse?: SpouseInput;
  dependents: Dependent[];
  isSingleParent: boolean;
  disabilityDeductions: DisabilityInput[];
}

interface LifeInsuranceInput {
  /** 新制度 / 旧制度 × 一般 / 介護医療 / 個人年金 の支払保険料 */
  new: { general: number; nursing: number; pension: number };
  old: { general: number; pension: number };
  /** 令和8年分の子育て世帯特例（23歳未満の扶養親族の有無）判定に使う */
  hasChildUnder23: boolean;
}

interface MedicalInput {
  paid: number;                  // 支払った医療費
  reimbursed: number;            // 保険金等で補填される金額
  selfMedication: number;        // セルフメディケーション税制対象額
  mode: 'auto' | 'medical' | 'selfMedication';  // autoは有利判定
}

/** 住宅ローン控除 */
interface HousingLoanInput {
  moveInYear: number;            // 2023
  years: number;                 // 13
  rate: number;                  // 0.007
  yearEndBalance: number;        // 対象年の年末残高
  borrowingCap: number;          // 借入限度額（住宅区分により3,000万〜5,000万）
  /** 住民税への繰越上限の適用ルール（入居年により異なる） */
  residentTaxCapRule: 'rule5pct97500' | 'rule7pct136500';
}

/** ふるさと納税 */
interface FurusatoInput {
  method: 'oneStop' | 'taxReturn';  // 医療費控除がある場合は taxReturn に強制
  donatedAmount: number;            // 実績（既に寄附済みの額）
  safetyRatio: number;              // 既定 0.9
}

/** 自治体設定 */
interface MunicipalityConfig {
  name: string;                     // '横浜市'
  prefectureName: string;           // '神奈川県'
  /** 所得割率。標準は市町村6% / 道府県4%。超過課税を反映する */
  municipalIncomeRate: number;      // 0.06
  prefecturalIncomeRate: number;    // 神奈川県: 0.04025（水源環境保全税0.025%上乗せ）※要確認
  /** 均等割 */
  municipalPerCapita: number;       // 3,000 + 横浜みどり税 900 ※要確認
  prefecturalPerCapita: number;     // 1,000
  forestTax: number;                // 森林環境税 1,000
  /**
   * ふるさと納税 特例分の20%枠の判定に用いる所得割率。
   * 特例分の計算では標準税率10%を用いる（超過課税分は含めない）のが実務の扱い。
   */
  useStandardRateForFurusato: boolean;  // 既定 true
}
```

### 2.3 出力

```ts
interface CalculationResult {
  income: {
    grossTotal: number;              // 給与収入合計
    salaryDeduction: number;         // 給与所得控除
    salaryIncome: number;            // 給与所得
    totalIncome: number;             // 合計所得金額
    nonTaxableBenefits: number;      // 育休給付金等（参考表示）
  };
  incomeTax: {
    deductions: DeductionBreakdown;  // 所得控除の内訳（所得税基準）
    taxableIncome: number;           // 課税総所得金額
    marginalRate: number;            // 限界税率
    calculatedTax: number;           // 算出所得税額
    housingLoanApplied: number;      // 所得税から控除した住宅ローン控除
    taxAfterCredits: number;         // 差引所得税額
    reconstructionTax: number;       // 復興特別所得税
    total: number;
  };
  residentTax: {
    deductions: DeductionBreakdown;  // 所得控除の内訳（住民税基準）
    taxableIncome: number;
    incomeLevyBeforeAdj: number;
    adjustmentCredit: number;        // 調整控除
    /** 調整控除後・税額控除前の所得割額（自治体の実効税率ベース） */
    incomeLevy: number;
    /** ★ふるさと納税 特例分20%枠の基準となる所得割額。
     *  useStandardRateForFurusato = true なら標準税率10%で算出する（§2.2） */
    incomeLevyForFurusatoCap: number;
```

## 2.4 永続化・エクスポート／インポート仕様

### 2.4.1 ストレージ設計

| 保存先 | 内容 | 理由 |
|---|---|---|
| **IndexedDB** DB名 `taxsim`, store `appData`, key `'root'` | `AppData` 全体 | 構造化データを扱え、容量上限が大きい（数十MB〜）。本アプリのデータ量では余裕がある |

### 2.4.3 スキーマ移行（NFR-13）

```ts
type Migration = (data: any) => any;

const MIGRATIONS: Record<number, Migration> = {
  // 1 → 2（Issue #48）: MonthlyRecord に社会保険料の内訳フィールドを追加した。
  // どちらも省略可能で、省略時は一括入力として扱うため値の書き換えは不要。
  2: (d) => ({ ...d, schemaVersion: 2 }),
};

export const CURRENT_SCHEMA_VERSION = 2;

export function migrate(data: any): AppData {
  if (typeof data?.schemaVersion !== 'number') {
    throw new ImportError('形式が認識できません。TaxSim がエクスポートしたファイルですか？');
  }
  if (data.schemaVersion > CURRENT_SCHEMA_VERSION) {
    throw new ImportError(
      'このファイルは新しいバージョンのアプリで作成されています。アプリを更新してください。'
    );
  }
  let d = data;
  for (let v = d.schemaVersion + 1; v <= CURRENT_SCHEMA_VERSION; v++) {
    const m = MIGRATIONS[v];
    if (!m) throw new ImportError(`バージョン ${v} への移行手順が見つかりません。`);
    d = m(d);
  }
  return validate(d);   // 型・必須項目・数値範囲の検証
}
```

**原則: 移行できない場合は必ず例外を投げる。**部分的に読み込んで欠損したまま計算を続けることは、誤った税額を出す最悪のケースにつながる。

**バージョンを上げる基準**: 新しいフィールドが省略可能で旧データをそのまま読めても、「新しいアプリで書いたデータを旧アプリが読んだときに黙って別の値で計算する」場合はバージョンを上げる。上げておけば旧アプリ側が「新しいバージョンのアプリで作成されています」として取り込みを拒否できる（PWAのキャッシュにより旧バージョンが端末に残りうるため、実際に起こりうる経路である）。v2（Issue #48）は、内訳入力の月で旧アプリが古い一括入力額を使ってしまうため、この基準に該当する。

### 2.4.6 暗号化エクスポート（FR-27）

```ts
async function encrypt(plain: string, passphrase: string): Promise<Uint8Array> {
  const salt = crypto.getRandomValues(new Uint8Array(16));
  const iv   = crypto.getRandomValues(new Uint8Array(12));

  const baseKey = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(passphrase), 'PBKDF2', false, ['deriveKey']
  );
  const key = await crypto.subtle.deriveKey(
    { name: 'PBKDF2', salt, iterations: 310_000, hash: 'SHA-256' },
    baseKey,
    { name: 'AES-GCM', length: 256 },
    false, ['encrypt']
  );
  const cipher = new Uint8Array(await crypto.subtle.encrypt(
    { name: 'AES-GCM', iv }, key, new TextEncoder().encode(plain)
  ));

  // ファイル形式: magic(8) | version(1) | salt(16) | iv(12) | ciphertext
  return concat(MAGIC, new Uint8Array([1]), salt, iv, cipher);
}
```

- パスフレーズを紛失した場合、**復号手段は存在しない**ことをUIで明示する。
- 暗号化はあくまでファイル持ち出し時の保護であり、IndexedDB上のデータは平文で保存される（§2.4.7）。

### 2.4.7 セキュリティ上の限界（明示する制約）

| 事項 | 実際のところ |
|---|---|
| 人物プロファイルの切替 | **アクセス制御ではない**。同じブラウザを使える人は誰でも全人物のデータを見られる |
| IndexedDB の中身 | 平文。DevTools から閲覧可能 |
| パスワードロック機能 | 静的配信・クライアントサイドでは、鍵もコードも手元にあるため意味のある防御にならない。**実装しない**（できないことを「できる」と見せかけるのが最も危険） |
| 推奨する運用 | 共有端末では利用後に「全データ削除」（FR-31）を実行し、バックアップは暗号化エクスポートで持ち出す |

#### 3.3.1 調整控除

所得税と住民税の人的控除額の差額（基礎控除の差は **50,000円** で固定して扱う）の合計を `D` とする。

```
課税総所得金額 ≦ 2,000,000 の場合:
    調整控除 = min(D, 課税総所得金額) × 5%
課税総所得金額 > 2,000,000 の場合:
    調整控除 = max( (D − (課税総所得金額 − 2,000,000)) × 5% , 2,500 )
※合計所得金額 2,500万円超は適用なし
```

> **⚠ 要確認パラメータ**: 令和7年度・令和8年度改正で所得税の基礎控除が大幅に引き上げられたが、調整控除で用いる基礎控除の差額は法令上5万円で据え置かれている扱い。改正の反映状況を必ず確認すること。この値は所得割額に直接効くため、上限額への影響が大きい。

#### 3.3.2 ふるさと納税（寄附金税額控除）

```
対象寄附額 = min(寄附額, 総所得金額等 × 30%)

基本分 = (対象寄附額 − 2,000) × 10%

特例分 = (対象寄附額 − 2,000) × (90% − 所得税率 × 1.021)
         ただし  特例分 ≦ 所得割額 × 20%
         （所得割額 = 調整控除後・住宅ローン控除等の税額控除前）

所得税分（寄附金控除）= 所得控除として (対象寄附額 − 2,000) を総所得から控除
                         ※控除対象は総所得金額等の40%が上限
```

**適用順序（住民税の税額控除）**: 調整控除 → 寄附金税額控除 → 住宅借入金等特別税額控除 の順で所得割額から控除する。すなわち特例分20%枠の判定には住宅ローン控除は影響しない。ただしこの点は情報源により説明が分かれるため、`§4.3` の保守的モードを用意する。

## 4. 計算エンジン仕様

### 4.1 中核となる設計判断: 差分シミュレーション方式

一般的なシミュレータは近似式
`上限 ≒ 所得割額 × 20% ÷ (90% − 所得税率 × 1.021) + 2,000`
を用いるが、この式は以下を扱えない。

- 住宅ローン控除により所得税額が既にゼロ → 所得税分の軽減が発生しない
- 寄附金控除により課税所得が下がり、**税率帯をまたぐ**（限界税率が変わる）
- 寄附金控除により所得税額が下がり、**住宅ローン控除の切り捨てが増える**
- 医療費控除・育休減収により所得割額が非線形に変動する

そこで本アプリは、**「寄附なし」「寄附額D」の2ケースで税額を丸ごと計算し、その差から自己負担額を求める**。

```
自己負担(D) = D − { (所得税額+復興税)ₙₒₙₑ − (所得税額+復興税)_D }
                 − { 住民税所得割ₙₒₙₑ − 住民税所得割_D }
```

この定義なら、上記の相互作用がすべて自動的に織り込まれる。上限額は

```
上限 = max { D ∈ 1,000円刻み | 自己負担(D) ≦ 2,000 }
```

を**二分探索**で求める。単調性（Dの増加に対し自己負担が非減少）は税額計算の性質から成立するが、実装では探索後に前後を線形検証してガードする。

### 4.2 疑似コード

```ts

  // --- 1. 所得 ---
  const gross = sumMonthlySalary(profile.income) + sumBonuses(profile.income)
              + profile.income.otherSalaryIncome;
  const salaryDeduction = calcSalaryDeduction(gross, params);
  const salaryIncome    = Math.max(0, gross - salaryDeduction);
  const totalIncome     = salaryIncome;            // 給与のみを前提

  // --- 2. 所得控除（所得税基準） ---
  const socialIns = profile.deductions.socialInsuranceOverride
                 ?? sumSocialInsurance(profile.income);   // 育休免除月は0
  const medical   = calcMedicalDeduction(profile.deductions.medical, totalIncome, params);
  const lifeIns_i = calcLifeInsurance(profile.deductions.lifeInsurance, params.incomeTax);
  const basic_i   = lookupBasicDeduction(totalIncome, params.incomeTax.basic);
  const donationDeduction = donation > 0
      ? Math.max(0, Math.min(donation, totalIncome * 0.4) - 2000)
      : 0;

  const dedTotal_i = basic_i + socialIns + lifeIns_i + medical + otherDeductions_i + donationDeduction;

  // --- 3. 所得税 ---
  const taxable_i = floor1000(Math.max(0, totalIncome - dedTotal_i));
  const { rate, offset } = lookupTaxRate(taxable_i, params.incomeTax.brackets);
  const calculatedTax = Math.max(0, taxable_i * rate - offset);

  // 住宅ローン控除（所得税）
  const hlCredit = calcHousingLoanCredit(profile.housingLoan);          // 残高×0.7%
  const hlInIncomeTax = Math.min(hlCredit, calculatedTax);
  const taxAfterCredits = floor100(calculatedTax - hlInIncomeTax);
  const reconstruction  = floor100(taxAfterCredits * 0.021);

  // --- 4. 住民税 ---
  const lifeIns_r = calcLifeInsurance(profile.deductions.lifeInsurance, params.residentTax);
  const basic_r   = params.residentTax.basicDeduction;                  // 430,000
  const dedTotal_r = basic_r + socialIns + lifeIns_r + medical + otherDeductions_r;
                     // ※寄附金は住民税では税額控除。所得控除に含めない

  const taxable_r = floor1000(Math.max(0, totalIncome - dedTotal_r));
  const levyRate  = profile.municipality.municipalIncomeRate
                  + profile.municipality.prefecturalIncomeRate;         // 例 0.10025
  const levyBefore = taxable_r * levyRate;
  const adjustment = calcAdjustmentCredit(taxable_r, humanDeductionDiff(profile), params);

  const incomeLevy = Math.max(0, levyBefore - adjustment);

  /** ★特例分20%枠の基準となる所得割額。超過課税分を含めない標準税率10%で算出する（§2.2） */
  const capRate = profile.municipality.useStandardRateForFurusato
                ? params.residentTax.municipalIncomeRateStandard
                  + params.residentTax.prefecturalIncomeRateStandard    // 0.10
                : levyRate;
  const incomeLevyForFurusatoCap = Math.max(0, taxable_r * capRate - adjustment);

  // ふるさと納税の税額控除
  const target = Math.min(donation, totalIncome * 0.3);
  const basicCredit = donation > 0 ? Math.max(0, target - 2000) * 0.10 : 0;
  const specialRaw  = donation > 0 ? Math.max(0, target - 2000) * (0.90 - rate * 1.021) : 0;
  const specialCap  = incomeLevyForFurusatoCap * 0.20;
  const specialCredit = Math.min(specialRaw, specialCap);

  // 住宅ローン控除（住民税）: 寄附金税額控除の後に適用
  const afterFurusato = Math.max(0, incomeLevy - basicCredit - specialCredit);
  const hlCarry   = hlCredit - hlInIncomeTax;
  const hlCap     = Math.min(taxable_i * 0.05, 97500);   // 課税総所得金額等ベース
  const hlInResident = Math.min(hlCarry, hlCap, afterFurusato);
  const hlWasted  = hlCarry - hlInResident;              // ★切り捨て損失

  const incomeLevyFinal = floor100(Math.max(0, afterFurusato - hlInResident));
  const perCapita = profile.municipality.municipalPerCapita
                  + profile.municipality.prefecturalPerCapita
                  + profile.municipality.forestTax;

  return {
    incomeTaxTotal: taxAfterCredits + reconstruction,
    residentIncomeLevy: incomeLevyFinal,
    incomeLevyBase: incomeLevyForFurusatoCap,
    marginalRate: rate,
    housingLoan: { credit: hlCredit, inIncomeTax: hlInIncomeTax,
                   inResident: hlInResident, wasted: hlWasted },
    /* ...trace... */
  };
}

/** 自己負担額 */
function selfBurden(profile: YearProfile, D: number, params: TaxParams): number {
  const base = calcTaxes(profile, 0, params);
  const with_ = calcTaxes(profile, D, params);
  const reduction = (base.incomeTaxTotal - with_.incomeTaxTotal)
                  + (base.residentIncomeLevy - with_.residentIncomeLevy);
  return D - reduction;
}

/** 上限額の探索 */
function findFurusatoLimit(profile: YearProfile, params: TaxParams): number {
  const STEP = 1000;
  let lo = 0;
  let hi = 2_000_000;                       // 十分大きい初期上限

  if (selfBurden(profile, STEP, params) > 2000) return 0;   // 非課税等

  while (hi - lo > STEP) {
    const mid = floorTo((lo + hi) / 2, STEP);
    if (selfBurden(profile, mid, params) <= 2000) lo = mid; else hi = mid;
  }
  // 単調性ガード: lo の前後 ±5ステップを線形検証
  for (let d = lo + STEP; d <= lo + STEP * 5; d += STEP) {
    if (selfBurden(profile, d, params) <= 2000) lo = d;
  }
  return lo;
}
```

### 4.3 保守的モード（R-03対応）

`§3.3.2` の適用順序について、「住宅ローン控除を先に控除した後の所得割額を20%枠の基準とする」という解釈も存在する。設定で以下を切替可能にする。

| モード | 20%枠の基準 | 用途 |
|---|---|---|
| `standard`（既定） | 調整控除後・税額控除前の所得割額 | 総務省・主要ポータルの説明に合致 |
| `conservative` | 住宅ローン控除適用後の所得割額 | 安全側。両者を併記し、低い方を推奨額の根拠とする |

UI では両方の値を並記し、差額を「解釈による振れ幅」として表示する。

年分の切替と追加（FR-01、Issue #49）:

- 「年度切替」は、その人物に作成済みの年分を列挙する。
- 「年分を追加」は、税制パラメータを収録している年分（`src/taxParams/supportedYears.ts` の `SUPPORTED_TAX_YEARS`）のうち、その人物にまだ作成されていないものを列挙する。**過去の年分も選べる**（源泉徴収票・住民税決定通知書との検算には過去年分の入力が必要なため）。追加できる年分が無い場合は、その旨を表示して追加UI自体を出さない。
  - 収録していない年分を作成させないのは、パラメータが無い年分のプロファイルが計算不能（§8のfail closed）であり、検算にもシミュレーションにも使えないため。
  - 追加時は前年のプロファイルがあればコピーし、無ければ人物の既定値からの空データとする。過去年分の追加では通常は後者になる。
  - 作成済みの年分を選択肢から除くことに加え、store側でも上書きを拒否してエラーを表示する（入力済みデータを失う操作のため、UIの前提が崩れた場合にも備える）。
- 表示中の年分が今年より前の場合は、「過去の年分（検算用）であり、ふるさと納税の上限額・残枠は参考値である」ことを明示する。今年分と同じ画面・同じ見た目のまま出すと、寄附できる残枠と取り違えるため。

### S-02 収入入力
- 12ヶ月グリッド。各月に「給与」「社会保険料」「実績/見込み」トグル。

### S-04 住宅ローン控除
所得税 → 住民税 → 切り捨て の流れをサンキー図／積み上げ棒で可視化。

```
控除可能額 ￥XXX,XXX
  ├─ 所得税から控除    ￥ XX,XXX
  ├─ 住民税から控除    ￥ XX,XXX  (上限 ￥97,500 / 課税総所得×5% = ￥XX,XXX)
  └─ 切り捨て          ￥ XX,XXX  ⚠
```

入力欄のうち「借入限度額」は利用者が意味を判断しにくいため、欄の直下に次を常時表示する（Issue #50）。

- 何の値か: 控除の対象にできる年末残高の上限額。住宅の種類（認定住宅・ZEH水準・省エネ基準など）と入居年で決まり、住宅区分により3,000万〜5,000万円程度。
- 調べ方: 国税庁「住宅借入金等特別控除」の区分表、または確定申告・年末調整で使った控除の計算明細書。金額は税制パラメータ（`public/taxParams`）に持たないため、断定せず目安と一次情報の確認先のみを示す。
- 効き方: 控除額は `min(年末残高, 借入限度額) × 控除率` であること、および現在の入力での控除対象残高。
- 借入限度額が0円のままの場合は、住宅ローン控除額が0円として計算される旨を注意表示する。

## 9. 付録: 利用者ケースの計算順序（2026年分）

1. 2026年1〜6月の給与・社会保険料を実績入力（1月は育休で0）
2. 7〜12月を直近実績で埋め、賞与見込みを入力（査定期間の育休を考慮）
3. 生命保険料・社会保険料・医療費（2026年分）・扶養情報を入力
4. 住宅ローンの2026年末残高見込みを入力
5. → 所得税・住民税を算出
6. → 差分シミュレーションで上限額を算出
7. → 安全率90%の推奨額を確認、警告を確認
8. → **医療費控除があるなら確定申告方式で寄附する**（ワンストップ特例申請書は送らない）
9. → 11〜12月に実績で再計算し、残枠を使い切る
